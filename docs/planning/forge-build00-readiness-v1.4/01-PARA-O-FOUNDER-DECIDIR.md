# Duas decisões para o Founder

Esta página pede dois sim ou não. Nada nesta página está aprovado. Dizer sim mais tarde não deixa o Forge pronto para construir e não autoriza o início da obra.

O que você já decidiu continua valendo e não está em votação: as regras de integração, as regras dos adaptadores e a base escrita v1.7. O registro está em `docs/planning/forge-planning-closure-v1.0/01-DECISOES-DO-FOUNDER.md`.

As contas e os papéis dos spikes continuam os da v1.1. Esta página não mexe neles.

## 1. Quem executa o trabalho

**Recomendação, ainda não aprovada.** Agentes de IA, identificados pela função, podem executar o trabalho. Não é preciso contratar alguém nem escrever o nome de uma pessoa em cada item.

**O que esta recomendação abrange, se você disser sim:**

- a) as 41 histórias;
- b) os nove spikes do BUILD-00.

A regra é a mesma nos dois: a função do agente substitui o nome de uma pessoa. Não cria uma regra diferente para os spikes.

**O que o sim não faz, mesmo abrangendo histórias e spikes.**

- Não calibra horas nem timebox. As faixas já escritas continuam estimativa, não compromisso. A calibração segue pendente.
- Não autoriza iniciar o BUILD-00. Essa autorização continua humana, separada e não foi concedida. Cobrir os spikes nesta regra não permite executá-los.

**Por quê.** A função de cada história já está na base. O plano dos spikes também já indica uma função. Pedir um nome humano por item não muda o produto; só segura a execução.

**O que isso muda, se você disser sim.** O texto antigo pede uma pessoa nomeada para a tarefa poder ser executada. O sim trocaria essa leitura nas 41 histórias e nos nove spikes: a função do agente passaria a bastar, e o nome deixaria de ser exigido item por item. Os arquivos antigos não foram alterados. Até o sim, essa troca não vale.

**Se disser não.** Continua a regra atual: sem uma pessoa nomeada, a tarefa e o spike não ficam operacionalmente prontos.

## 2. Se Claude Code e AIOX discordarem

**Recomendação, ainda não aprovada.**

- Claude Code coordena a implementação dentro da base que você já aceitou. Essa coordenação também faz parte desta recomendação; ainda não é uma decisão sua.
- AIOX é o caminho preferido. Se ele não estiver disponível, usa-se o reserva que a história F-013 já escreveu: o Forge chama o motor direto, só para ação interna, sem publicação e sem efeito externo.
- Durante o uso desse caminho alternativo, só podem ser executadas ações já claramente permitidas pela regra da F-013. Se surgir dúvida sobre escopo, segurança ou interpretação técnica, o trabalho para e a questão vem para você. Claude Code não pode resolver essa dúvida sozinho. A ausência do AIOX não lhe dá esse poder.
- Se a discordância for sobre o que entra no trabalho ou sobre segurança, o trabalho para e a decisão vem para você. Se não estiver claro de que tipo é a discordância, também para.
- Detalhe técnico dentro da base já aceita não vem para você só quando for possível determinar com segurança que ele cabe nessa base. Quem pode determinar isso: Claude Code e AIOX, em conjunto. Os dois precisam concordar que o ponto cabe na base já aceita. Claude Code não decide isso sozinho. AIOX também não.
- Se os dois não concordarem, ou se não der para determinar com segurança que a discordância está dentro da base aceita, o trabalho para e a questão vem para você.
- Codex continua só como revisor independente das evidências. Não decide o produto, não escolhe o vencedor e não classifica se a discordância está no escopo.
- Deixar de preferir o AIOX continua exigindo uma decisão de mudança, como a base já diz.

**Se disser não.** A v1.1 continua valendo neste ponto: não há regra e ninguém escolhe um vencedor.

A frase sobre decisões de alto impacto é só um resumo. Não é a lista completa. A fonte desses gates continua sendo os documentos-base, entre eles a aprovação humana de cada publicação em produção já descrita em FDP-18 v1.3 e na história F-029 do FDP-19A v1.7. Esta página não reescreve esses documentos e não reduz o que eles exigem.
